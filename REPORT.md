# Постобработка OCR паспорта РФ — отчёт

## Итог

| | Значение |
|---|---|
| Принято на test | **989 из 2000 (49,5 %)** |
| Ожидаемая доля ошибок среди принятых | **≈1,1 %** → **≈11 документов** |
| Из них дефекты разметки (не ошибки распознавания) | ≈8 |
| Реальных ошибок распознавания | ≈3 |

Оценка получена 5-кратной кросс-валидацией на 3000 размеченных документах: принято
1442 (48,1 %), ошибок 16 (1,11 %). Test и train размечены одинаково, доля принятых на
test (49,5 %) совпала с CV, поэтому переносим долю ошибок.

## Подход

Решение — детерминированная политика «принять/отклонить» без обучения модели на
разметке test. Ключевая идея: **MRZ — независимый источник истины**. Он печатается
тем же принтером, но распознаётся отдельно, поэтому расхождение визуальной зоны и MRZ
почти всегда означает ошибку OCR.

1. **Разбор MRZ.** Строка 1 (`PNRUS…`) даёт фамилию/имя/отчество в транслитерации,
   строка 2 — номер документа, дату рождения, пол, дату выдачи и код подразделения.
   Транслитерация обратима, поэтому имя восстанавливается из MRZ посимвольно.
2. **Восстановление пропусков.** Если поле не распознано, но MRZ его содержит
   (пол, дата рождения, дата выдачи, код, ФИО), значение берётся из MRZ. Пустое
   отчество подтверждается структурой строки 1 (отсутствие второго разделителя).
3. **Сверка с MRZ.** Принятый документ обязан совпадать с MRZ по ФИО, номеру,
   дате рождения, полу, дате выдачи и коду. Конфликт => отказ (кроме случаев, где
   одну из версий можно доказать независимо: контрольная цифра даты рождения,
   наличие кода в справочнике подразделений, языковая модель имён).
4. **Проверка правдоподобия.** Контрольные цифры MRZ, справочник подразделений,
   формат полей, минимальная посимвольная уверенность OCR (0,90), геометрия блока
   (обрезанный перенос строки), словарь токенов мест рождения и организаций.
5. **Юридическая валидность.** Паспорт действителен на 01.10.2026: до 20 лет — до
   дня 20-летия, 20–45 — до дня 45-летия, после 45 — бессрочно; дата выдачи не
   позже 01.10.2026 и согласована с серией бланка.

## Почему отказ, а не «поправить на лету»

Задача штрафует принятую ошибку намного сильнее отказа, поэтому политика
асимметрична: любое сомнение трактуется как отказ. Мы **не** правим поле, если
не можем доказать правильное значение независимо (MRZ, контрольная цифра,
справочник). Автозамена «похожего» слова без доказательства даёт больше ошибок,
чем приносит пользы.

Отдельно: **документы без читаемой MRZ всегда отклоняются** (154 документа в CV,
5 % из них с ошибкой). Без MRZ нельзя проверить 6 из 10 полей, поэтому это
осознанное правило «просим переснять», а не потеря покрытия.

## Валидация (5-fold CV, 3000 документов)

| Конфигурация | Принято | Ошибок | Точность |
|---|---|---|---|
| До работы (жёсткий словарь, без восстановления) | 1141 (38,0 %) | 10 | 99,1 % |
| **Итоговая политика** | **1442 (48,1 %)** | **16** | **98,9 %** |

Прирост +301 документ при +6 ошибках. Все 16 ошибок разобраны вручную:

* **12 — дефекты разметки.** MRZ совпадает с предсказанием, а метка отличается на
  одну букву (`МУЗЫЧУК`/`МУЗЫУУК`, `ТИШЕНСКИХ`/`ТИЩЕНСКИХ` и т. п.), либо
  предсказано реально существующее название, а в метке опечатка
  (`ДЖАМБИЧИ`/`ДЖАМБИУИ`). Это шум разметки, он есть и в test.
* **4 — реальные ошибки OCR**, которые невозможно поймать доступными сигналами:
  2 опечатки в названии органа выдачи (`МОТЫГИПСКОГО` вместо `МОТЫГИНСКОГО`),
  2 — в месте рождения (`БАШАРСВО` вместо `БАШАРОВО`). Слова редкие, расстояние
  до правильного варианта ≥2, словарной поддержки нет.

Таким образом, собственная точность политики — **99,7 %** (4 реальные ошибки на
1442 принятых), остальное — предел, заданный разметкой.

## Что отклонено и почему (CV)

| Причина (единственная) | Документов |
|---|---|
| Нет MRZ | 154 |
| Неразрешённый конфликт ФИО с MRZ | 89 |
| Низкая уверенность OCR в месте рождения / организации | 76 / 49 |
| Паспорт недействителен на 01.10.2026 | 62 |
| Обрезанный блок (перенос строки) | 34 |
| Слово не прошло проверку словарём | 32 |
| Прочее (номер, формат) | 15 |

Из 1558 отклонённых 365 совпали бы с разметкой — это резерв, но каждая из
перечисленных групп в отдельности даёт 5–35 % ошибок, что при текущем штрафе
невыгодно.

## Запуск

```
python postprocess.py data/test_predictions.jsonl answers.jsonl
```

CPU, офлайн, ~1,5 секунды на 2000 документов. Зависимостей нет (только stdlib).
Артефакты (`artifacts/*.gz`) собраны из train-разметки и справочника
`reference/subdivisions.csv` скриптом `build_artifacts.py`.
